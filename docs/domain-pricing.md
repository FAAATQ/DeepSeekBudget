# DeepSeek 峰谷计费规则（领域知识）

数据来源：<https://api-docs.deepseek.com/quick_start/pricing>
核实日期：**2026-09-12**（记录在 `deepseek.json` 的 `verifiedAt` 字段）

> **获取方式备注**：内置的 WebSearch 返回 403、WebFetch 被域名策略挡下。最终是用 `curl` 把页面抓下来、用脚本剥掉标签后读取的。**工具的失败不等于数据不存在** —— 这条经验值得记。

## 一、时段规则

| | |
|---|---|
| **高峰时段** | 周一至周五 **01:00–04:00** 与 **06:00–10:00**（**UTC**） |
| **北京时间等价** | 周一至周五 **09:00–12:00** 与 **14:00–18:00** |
| **空闲时段** | 其余全部时间 |
| **周末** | 全天空闲 |
| **价格关系** | 空闲价 = 高峰价的 **一半** |
| **适用范围** | **全平台统一，不随模型变化** |

**这是两条窗口，不是一条。** 容易误读成一条连续的 16:30→00:30 窗口，并因此以为「星期几不是个因素」—— 实际是两条窗口 + 严格的周一至周五限制。

### 半开区间

所有时段按 **`[start, end)`** 处理。`04:00` 属于**空闲**的开始，不属于高峰的结束。边界测试专门盯这个：

```
03:59:59 → 高峰
04:00:00 → 空闲   ← 半开区间，端点归右
```

### 最长的等待：63 小时

**北京时间周五 18:00 → 周一 09:00 = 63 小时。**

这是本产品的**招牌数字** —— 整个「看一眼，就知道现在值不值得用」的价值，在这个场景下被放大到极致：如果现在是周五晚上，用户真正需要知道的是「接下来两天半都是谷价，可以放心跑批」。

## 三、数据结构

价格定义与计算引擎**完全解耦**：引擎不认识 DeepSeek，它只认识 JSON 里描述的时段与价格。加一个 provider = 加一个 JSON 文件（`crates/schedule/config/providers/*.json`）。

```jsonc
{
  "provider": "deepseek",
  "defaultCurrency": "CNY",
  "verifiedAt": "2026-09-12",
  "notes": { "en": [...], "zh": [...] },   // 按语言分键
  "schedule": {
    "referenceUtcOffsetMinutes": 0,        // 星期几在这个时区里判定
    "referenceLabel": "UTC",
    "weekly": [
      { "days": ["Mon","Tue","Wed","Thu","Fri"],
        "windows": [["01:00","04:00"], ["06:00","10:00"]] }
    ]
  },
  "models": [
    { "id": "...", "label": "...", "version": "...",
      "prices": { "CNY": { "output": { "offPeak": 4, "peak": 8 } } } }
  ]
}
```

**两个设计细节**：

1. **`notes` 按语言分键**，和 `prices` 按货币分键是同一个模式 —— 都是「同一个字段的多种表示」，不是两份文案。
2. **价格用整数/定点写法**（`1`、`4`、`13.5`）而非字符串，格式化时再去掉尾随零（`prices_render_without_trailing_zeros`）。

## 四、花了多少，你能知道到什么程度

如果打算基于这套价格做用量统计，先知道官方 API 的边界在哪：

**两头能看见，中间是黑的。**

- **账户余额**（`GET /user/balance`）—— 账户级快照，按币种拆。**没有时间、模型或 API Key 维度**
- **单次请求的 `usage`** —— 精确到 token，且已按缓存命中 / 未命中拆开，正好对应计费的两档单价。
  注意流式必须显式设 `include_usage: true`，否则拿不到；且缓存命中是「尽力而为」，**不能按输入长度反推费用**
- **中间那层「谁在什么时候花了多少」没有任何接口。** 全站 10 个 API 接口里没有一个是账单或用量；
  控制台只能手动导出 CSV

想要按时间 / 模型 / key 拆分的消费明细，**只能自己代理请求逐次记账** —— 那是另一个产品。
另外，**用余额差分反推消费是不可靠的**：充值会让差额变负，赠金过期会凭空减少，而且账户级数据不区分是哪个客户端花的。

## 五、中文措辞用官方原词

中文界面用 **「高峰」/「空闲」**，直接取自 DeepSeek 官方中文页；**不是**自创的「峰值时段 / 谷时」之类译法。

理由：用户是从官方页面认识这个概念的，界面上出现另一个词会增加一次不必要的翻译。

同理，`render_days` 输出的区间分隔符，中文用 **「至」**（`周一至周五`）而不是 en dash（`周一–周五`）—— 后者是英文排版习惯。**这个 bug 是测试先发现的** —— 测试是对的，代码是错的。
